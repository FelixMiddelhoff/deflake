# CLI Reference

Deflake is a dotnet global tool that investigates why a test is flaky by rerunning it under controlled conditions.

## Installation

Install deflake as a global dotnet tool:

```bash
dotnet tool install -g Deflake
```

Verify the installation:

```bash
deflake --version
```

## Global Options

```
deflake --help | -h | help      Show help information
deflake --version | -v          Show version (0.1.0)
```

## Commands

### investigate

Reruns a failing test under controlled conditions, changing one factor at a time to identify the root cause of flakiness.

#### Usage

```bash
deflake investigate <project|solution> [options]
```

#### Arguments

- `<project|solution>` — Path to a `.csproj`, `.vbproj`, or `.sln` file. Required.

#### Options

- `--test <FQN>` — Fully qualified name of a test to investigate. May be repeated to investigate multiple tests. If not specified, all tests are investigated.

- `--from-trx <file>` — Read failing tests from a TRX (Visual Studio Test Results) file instead of running them first.

- `--runs <n>` — Number of runs to execute before deflake adapts the run count based on confidence. Default: 20.

- `--max-runs <n>` — Maximum number of runs per condition. Default: same as `--runs`.

- `--timeout <minutes>` — Time budget for the entire investigation in minutes. Default: 60 minutes. A test investigation is cancelled when this budget is exhausted.

- `--framework <tfm>` — Target framework moniker (e.g., `net8.0`, `net6.0`). If not specified, deflake uses the project's default framework.

- `--configuration <c>` — Build configuration (`Debug`, `Release`, etc.). Default: Debug.

- `--no-build` — Skip the build step before testing. Useful when the project is already built.

- `--report <dir>` — Write reports to the specified directory instead of printing to console. Directory is created if it doesn't exist.

- `--format text|markdown|json` — Output format for reports. 
  - `text` (default) — Human-readable text format with tables and sections.
  - `markdown` — Markdown format suitable for documentation.
  - `json` — JSON format for parsing and integration.

#### Exit Codes

- `0` — All tests passed or had conclusive verdicts (no inconclusives).
- `1` — One or more tests have an `Inconclusive` verdict (investigation was not decisive enough).
- `2` — Usage error (invalid arguments, missing files, etc.).
- `3` — Build failed or test setup error.
- `4` — Investigation timeout or cancelled by user (Ctrl+C).

#### Examples

Investigate a single failing test:

```bash
deflake investigate MyProject.csproj --test "MyNamespace.MyTest.FailingTest"
```

Investigate multiple tests with a longer timeout:

```bash
deflake investigate MyProject.csproj --test "Test1.FlakyTest1" --test "Test1.FlakyTest2" --timeout 120
```

Generate a markdown report in a directory:

```bash
deflake investigate MyProject.csproj --report ./reports --format markdown
```

Investigate with custom run counts:

```bash
deflake investigate MyProject.csproj --runs 50 --max-runs 100 --timeout 90
```

### repro

Run the reproduction command from a verdict to verify it still fails.

#### Usage

```bash
deflake repro <report.json>
```

#### Arguments

- `<report.json>` — Path to a JSON report file generated by the investigate command.

#### Status

This command is not yet implemented.

### explain

Get detailed information about a specific verdict type or a test verdict by its ID.

#### Usage

```bash
deflake explain <VERDICT-ID>
```

#### Arguments

- `<VERDICT-ID>` — The ID or name of a verdict type (e.g., `OrderDependent`, `TimingSensitive`).

#### Status

This command is not yet implemented.

## Verdict Output Format

### Text Format (Default)

The text format includes:

- **Test** — Fully qualified name of the test.
- **Assembly** — Assembly name.
- **Verdict** — The type (e.g., `Inconclusive`, `OrderDependent`, `TimingSensitive`).
- **Confidence** — How certain the verdict is (0%–100%).
- **Evidence** — A table showing pass/fail rates under different conditions.
  - Columns: Condition (factor=value), Passed, Failed, Rate with confidence interval.
- **Not Tested** — Factors that were not tested or tests that were incomplete.
- **Suspect Tests** — Tests that appear to be polluting or causing the failure.
- **Suspect Members** — Code members from stack traces that may be involved.
- **Repro Command** — A copy-paste command that reproduces the failure.
- **Repro Verified** — Whether the reproduction command was re-run and confirmed.
- **Notes** — Additional context and warnings.

### Example Output

```
Test: MyNamespace.MyTest.MyFlakyTest
Assembly: MyProject
Verdict: OrderDependent
Confidence: 92%

Evidence:
Condition            | Passed | Failed |                      Rate
---------------------+--------+--------+--------------------------
Isolation=Alone      |     15 |      5 | 25.0% (95% 8.7%–48.7%)
Isolation=WithOthers |      0 |     20 | 100.0% (95% 83.2%–100.0%)

Suspect Tests:
  - MyNamespace.MyTest.PollutingTest

Repro Command:
dotnet test MyProject.csproj --no-build --filter "FullyQualifiedName=MyNamespace.MyTest.MyFlakyTest" --runclass "MyNamespace.MyTest.PollutingTest" --runclass "MyNamespace.MyTest.MyFlakyTest"

Repro Verified: True

Notes:
  - The test fails significantly more often when other tests run before it.
```

## Integration with CI/CD

### GitHub Actions Example

```yaml
- name: Investigate flaky tests
  run: deflake investigate MyProject.csproj --report ./deflake-reports --format markdown --timeout 120

- name: Upload reports
  uses: actions/upload-artifact@v3
  if: always()
  with:
    name: deflake-reports
    path: ./deflake-reports
```

### Azure Pipelines Example

```yaml
- task: DotNetCoreCLI@2
  displayName: Investigate flaky tests
  inputs:
    command: 'custom'
    custom: 'tool'
    arguments: 'run deflake -- investigate $(System.DefaultWorkingDirectory)/MyProject.csproj --report $(Build.ArtifactStagingDirectory)/deflake-reports --format markdown'
```
